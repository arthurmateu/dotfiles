## Coding preferences
- Keep things simple
- Tests are nice when focused
- I heavily dislike comments; if something isn't understood just by reading the code, the code itself is bad.
- Things should stay in sync; code also affects tests and documentation

### Python preferences
- Default to `uv`

## Work
- I encourage you to make quick playwright scripts, so you can take screenshots and interact with my browser with it

## Pull requests
- Follow repo conventions, including titles and descriptions.
- For PR descriptions, remember that humans read through and analyze it; focus on writing what was the problem, and what is your solution to it. You can include on the notes section part of your investigation, if relevant.
- First write your code and then let me analyze through the diffs
- When pushing and making a PR, opt for making a draft
- When checking reviewer's comments on a PR I have, don't respond directly; mention it to me and tell me your thoughts on it. Reason behind this is to avoid skill atrophy and have me understand what is actually happening
